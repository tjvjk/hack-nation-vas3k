### Technical Tips and Tools

- Top-tier coding tools: Codex, Claude Code; if no access, use Pico and OpenCode (free LLM APIs)
- Free LLM APIs: check OpenRouter for connectable models
- Open-weight models: Hugging Face (spaces + model suggestions)
- Image/audio generation APIs: Replicate (free starter credits)
- Links to all resources will be shared in chat
- Build strategy:
  - Define the smallest realistic core scope and build the riskiest part first
  - Mock non-core parts (e.g. scrapers, auth, dashboards) to stay focused
  - Maintain a working end-to-end flow at all times; commit to GitHub/GitLab continuously
  - Add polish and extra features only after core flow is stable

### Presentation and Pitch Advice

- Start working on the presentation from day one, not the last minute
- One-sentence problem/solution frame: “We help [who] solve [problem] by [solution]”
- Demo structure:
  1. Problem (20 seconds)
  2. Solution overview (brief)
  3. Live working demo (half the presentation time)
  4. High-level technical diagram (no code, no file trees)
- Always have a pre-recorded backup demo video in case of technical failure
- Keep multiple browser tabs open for smooth switching during the pitch
- Hook the jury in the first seconds; they may be fatigued from other teams
- Emphasize impact: a polished pitch without clear impact won’t win
- Submit by at least 1 hour before the deadline; wrong-challenge submission is a real risk
- Local pitch session on Sunday with its own jury and prizes
- Organizers are scouting promising teams for a venture track and future initiatives
